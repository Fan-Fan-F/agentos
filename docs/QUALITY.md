## 第七轮：Timeline 回放竞态（2026-09-21）

- 真实临时 WebSocket 回归复现：回放读取期间的实时事件先于 history 到达，前端随后用 history 替换列表，可能漏掉快照之后的事件；快照重叠事件还可能重复。
- 修复：先订阅并暂存实时事件，history 发送后按事件 ID 排除快照内重叠项，再补发快照后的事件，随后转为实时推送。回放期间待发缓冲上限 4 MiB，超过则用 1013 关闭供重连；磁盘事件保留。
- 验证：构建通过；20 个测试文件、143 项通过，1 项 POSIX 专用测试跳过。真实 WebSocket 测试控制读取时序，验证 history 在先、重叠去重、后续实时推送及积压超限的持久化。独立真实进程/Git崩溃恢复与崩溃后接力通过，Agent 为 Stub 契约。
- 审批记录：上次应用修复命令因自动审批额度限制未执行，本轮重新正常审批后完成。独立恢复命令曾审批超时未执行，按提示重试一次后通过。未绕过审批。
- 范围：尚未解决历史文件全量读取/发送以及前端全量渲染的规模性能问题；不能据此声称完成长 Timeline 性能或真实 UI 审计。真实模型与云端验证状态不变，未推送、未合入 main。
